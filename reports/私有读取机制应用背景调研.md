# 私有读取机制应用背景调研

日期：2026-10-08

被评估机制（用户给定）：单服务器私有读取；变长记录填充后按容量档 2^k 分组为公开"信封"；客户端公开信封地址，对信封内位置做 PIR，本地解密。公开泄漏 = 信封地址（含长度档与 shard）、信封规模、请求次数与时序。

## 结论速览

- **A（私密 RAG / LLM agent 取回变长 passage）**：WWW、SIGIR、VLDB/SIGMOD、PETS 四个 venue 家族 Q1 为空 → 不可投；安全四会仅有 Panther（CCS 2025，单服务器私密 ANN，弱映射 [待核]）→ 可投但须正面对照 Panther 及 Tiptoe / Coeus / Compass（非目标 venue 占位者）。Q3 未发现同时满足"变长 + 长度档契约 + 单服务器"的系统；最近邻 Spruce（arXiv，padded bucket + 公开 bucket capacity，但两云模型 [待核]）。
- **B（私密关键词查找：倒排表 / 邻接表等变长列表）**：Q1 在 VLDB/SIGMOD、安全四会、PETS 均有接纳证据，但 Q3 发现 **SEAL（USENIX Security 2020）** 形式上满足三条（关键词列表变长 + ADJ-PADDING-x 把列表填到 x 的幂、可观测大小仅 ⌈log_x N⌉+1 种 + 单服务器 [单服务器原句待核]）→ 按用户规则 B 只能作对照、不能作主语。若 SEAL 核实后不满足（例如形式化泄漏定义并非档位级），则 B 翻转为 VLDB/SIGMOD、安全四会、PETS 三家族"可投但须正面对照"；WWW、SIGIR 无论如何不可投。
- **C（托管加密对象存储的私密点查）**：WWW、SIGIR 不可投；VLDB/SIGMOD 与安全四会有接纳证据；PETS 有弱证据（CODoH 2026 依赖 TEE、Mohito 2024 为 IoT 消息、SWiSSSE 2024 为 SSE）。Q3 无确认占位者；最近邻 Jia–Agarwal–Khandelwal（USENIX Security 2024，bin-pack 到最大对象尺寸 bin，是否多档 [待核]）与 Nakamori et al.（EuroS&P 2025 [venue 待核]，泄漏模型 [待核]）→ 可投但须正面对照二者及 vORAM（S&P 2016）。
- **总体取证限制**：本次调研在网络策略下无法打开任何一手文献站点；除 VLDB/SIGMOD 2025–2026 做了标题级完整筛查外，其他 venue 均为搜索引擎抽样；绝大多数英文原句为 [待核·搜索摘录]，无页码。
- **裁决翻转点（优先补核）**：SEAL 的单服务器措辞与形式化泄漏定义（决定 B 是否占位）；Jia et al. 2024 的 bin 是否多尺寸档、Nakamori et al. 2025 的泄漏模型（决定 C 是否占位）；Panther 的取回对象、Spruce 的服务器数、PIR-RAG / RAGtime-PIANO / P²RAG 的记录模型（决定 A 在安全四会的 Q1 与 Q3）。
- 本报告不下"新颖性"结论，只报证据与按规则的裁决。

#### WWW / SIGIR / VLDB-SIGMOD

- 未找到安全四会 2024–2026 论文中直接陈述 A 场景三要素的原句。Panther 摘要只陈述私密 ANN 的服务器模型（见 Q1），不涉及 passage 长度或内容加密。

#### PETS
- PURBs（Nikitin 等，PETS 2019，窗口外，非 RAG 社区）关于 2 的幂填充开销：
  - 原句："Padding to a power of two can impose up to 100% overhead by nearly doubling the object's size." 与 PADMÉ "at most 12% for tiny messages, which decreases gradually with message size."
  - 出处：PETS 2019，章节 [待核] — [arXiv 1806.03160](https://arxiv.org/pdf/1806.03160) [待核·搜索摘录]
  - 覆盖要素：②（长度可变 / 填充代价）。非 A 社区论文，仅作填充开销的旁证。

#### 其他 venue / 预印本（私密 RAG 社区自身）
- **PIR-RAG**（arXiv 2509.21325，预印本）
  - 原句 1："For a true RAG application, both Graph-PIR and the Tiptoe-style system would require K additional, expensive PIR queries to privately fetch the document content for the LLM."
  - 原句 2："fundamentally misaligned with the end goal of RAG, which requires the full content of the retrieved documents, not just their IDs."
  - 原句 3："A single PIR query over a database of millions of documents is still too slow and resource-intensive for an interactive user experience."
  - 出处：arXiv 2509.21325，章节 [待核] — [arXiv](https://arxiv.org/abs/2509.21325)、[PDF](https://www.arxiv.org/pdf/2509.21325) [待核·搜索摘录]
  - 覆盖要素：①（取回哪篇文档内容须对服务器隐藏）。不覆盖 ②③。
- **RAGtime-PIANO**（IACR ePrint 2026/231，预印本）
  - 原句："RAG-as-a-Service has emerged, in which third-party servers can be used to process client queries via an external database. Unfortunately, using such a service would expose the client's query to a third party." 与 "neither the query, any distances, nor retrieval information is known to the database hosting server."
  - 出处：ePrint 2026/231，章节 [待核] — [ePrint](https://eprint.iacr.org/2026/231.pdf) [待核·搜索摘录]
  - 覆盖要素：①；③ 仅为"第三方托管"而非加密（不完全覆盖）。
- **Spruce: Scalable Private Outsourced Retrieval Using Compact Embeddings**（arXiv 2609.03376，预印本）
  - 原句 ①："each cloud only sees uniformly random PIR selectors and mask corrections, plus public parameters and bucket capacity, so it learns neither the selected cluster IDs nor a query-dependent scan size."
  - 原句 ②："fixed-width content rows suppress per-document byte length, which blocks volume-based reconstruction attacks." 与 "fixed-width padding removes per-record byte length from setup leakage."
  - 原句 ③：协议 "never opens codes, embeddings, ranking, content, or queries"；标题即 "Private Outsourced Retrieval"。
  - 出处：arXiv 2609.03376，章节 [待核] — [arXiv](https://arxiv.org/pdf/2609.03376) [待核·搜索摘录]
  - 覆盖要素：①②③ **三要素齐备（本次唯一）**；但 Spruce 为两云 / 多服务器模型（见 Q3）。
- **PRAG: End-to-End Privacy-Preserving RAG**（arXiv 2604.26525，预印本）
  - 原句："To ensure the cloud learns nothing about document contents, these operations cannot be performed on plaintext and must instead be executed entirely in the ciphertext domain." 另有 "embedding inversion attacks have demonstrated that continuous embeddings are not opaque fingerprints"。
  - 出处：arXiv 2604.26525，章节 [待核] — [arXiv](https://arxiv.org/html/2604.26525v1) [待核·搜索摘录]
  - 覆盖要素：③。
- **Compass**（OSDI 2025，同行评审；ePrint 2024/1255）
  - 原句："ensuring the privacy of data, queries, and results, even if the server is compromised" 与 "In this setting, Compass also enables secure retrieval over an encrypted RAG (Retrieval-Augmented Generation) database."
  - 出处：OSDI 2025 摘要 — [OSDI 25](https://www.usenix.org/conference/osdi25/presentation/zhu-jinhao)、[ePrint 2024/1255](https://eprint.iacr.org/2024/1255) [待核·搜索摘录]
  - 覆盖要素：①③。
- **Tiptoe**（SOSP 2023）
  - 原句："Tiptoe is a private web search engine that allows clients to search over hundreds of millions of documents, while revealing no information about their search query to the search engine's servers."
  - 出处：ePrint 2023/1438 摘要 — [ePrint](https://eprint.iacr.org/2023/1438) [待核·搜索摘录]
  - 覆盖要素：①。语料公开（"a public web crawl with 360 million pages" [待核·搜索摘录]），不满足 ③。
- **Coeus**（SOSP 2021）
  - 原句（摘要）："Given a private string q and a remote server that holds a set of public documents D, how can one of the K most relevant documents to q in D be selected and viewed without anyone (not even the server) learning anything about q or the document?"
  - 出处：SOSP 2021 摘要 — [NSF PAR](https://par.nsf.gov/biblio/10316017) [待核·搜索摘录]
  - 覆盖要素：①。"public documents" 明确不满足 ③。
- 非 RAG 社区但关于 PIR 变长记录的原句（供裁决者区分"社区自己是否承认"）：见家族 C 表 Q2（Nakamori et al. 2025、HHG 2013）。
- **不计入**：Formally-Verified Private RAGs for LLMs（课程项目报告，非同行评审）— [PDF](https://royrinberg.com/assets/projects/papers/class_private_RAG.pdf)；其句 "even if the stored content itself is encrypted, access patterns can inadvertently reveal sensitive information about user queries or document contents" 仅作线索。
- **Q2 小结（A）**：① 与 ③ 在私密 RAG 社区有多源原句；② "passage 变长 + 填充开销" 仅 Spruce 一篇明确表述，且动机是防 volume 攻击。三要素同现于一篇的只有 Spruce。全部原句无页码。

- **Patel–Persiano–Yeo–Yung, "Mitigating Leakage in Secure Cloud-Hosted Data Structures: Volume-Hiding for Multi-Maps via Hashing"（CCS 2019）**
  - 原句："Volume leakage has recently been identified as a major threat to the security of cryptographic cloud-based data structures by Kellaris et al. [CCS'16] (see also the attacks in Grubbs et al. [CCS'18] and Lacharité et al. [S&P'18])."
  - 原句（定义，部分转述）："A volume-hiding leakage function keeps the number of values for any single key from being revealed, and only the maximum volume of a key is leaked." 与 "L_Setup = dsize, which is the leakage function that reveals the number n of total values in the multi-map."

  - **WWW：不可投**（Q1 空）。
  - **SIGIR：不可投**（Q1 空）。
  - **VLDB/SIGMOD：Q1 有接纳证据（Doc*、OBIR-tree、Grove；邻近 GORAM、Workload-Aware Encrypted Index）→ 但因 Q3 占位，B 只能作对照**。

### 4.2 C-Q2 问题存在性（三要素：① 读哪个对象敏感 / ② 对象大小可变 / ③ 内容外包且加密）

#### 安全四会
- **ObliviStore（Stefanov & Shi, S&P 2013）**
  - 原句："It is well-known that encryption alone is not sufficient for ensuring data privacy, since data access patterns can also leak a considerable amount of sensitive information."；引 Islam 等结果，access pattern 可泄漏 "up to 80% of the search queries made to an encrypted email repository"；摘要 "we must prevent information leakage not only through access patterns, but also through timing of I/O events."
  - 出处：§1 / Abstract [待核] — [ObliviStore PDF](https://www.cs.umd.edu/~elaine/docs/ObliviStore.pdf) [待核·搜索摘录]
  - 覆盖要素：①③（加密邮件库为例；时序亦为泄漏面）。
- **Path ORAM（Stefanov 等, CCS 2013 / JACM 2018）**
  - 原句："data encryption alone is often not enough to protect users' privacy in outsourced storage applications."；ORAM 定义 "a cryptographic construction that allows a client to access encrypted data residing on an untrusted storage server, while completely hiding the access patterns to storage."
  - 出处 [待核] — [PathORAM JACM PDF](https://people.csail.mit.edu/devadas/pubs/PathORAMJACM.pdf) [待核·搜索摘录]
  - 覆盖要素：①③。
- **Pancake（Grubbs 等, USENIX Sec 2020）**
  - 原句：攻击只需 "a passive persistent adversary"，即 "one that observes access patterns but does not actively performs accesses"；敌手 "both knows the distribution and obtains the transcript of (encrypted) queries and responses"；"Batch imposes bandwidth overhead exactly B× over a KV store that just uses encryption and leaks access patterns."
  - 出处 [待核] — [ePrint 2020/1501](https://eprint.iacr.org/2020/1501.pdf) [待核·搜索摘录]
  - 覆盖要素：①③；② 未见（间接证据指向等长值，见 Q3）。
- **Cash, Grubbs, Perry, Ristenpart（CCS 2015）**：Enron 邮件语料的 leakage-abuse attacks；count attack 基于 "access and size patterns leakage"（后半为综述转述）— [ePrint 2016/718](https://eprint.iacr.org/2016/718) [待核·搜索摘录 / 转述]。覆盖 ①②（size pattern）③。
- **Jia, Agarwal, Khandelwal, "Length Leakage in Oblivious Data Access Mechanisms"（USENIX Sec 2024, pp. 6417–6434）**
  - 原句（摘要）："explores the problem of preventing length leakage in oblivious data access mechanisms with passive persistent adversaries"；"designing mechanisms that prevent both length leakage and access pattern leakage requires navigating additional difficulties"（storage / bandwidth / leakage 三方权衡）。
  - 原句：padding-based scheme 叠加 ORAM/Pancake 只泄漏 "the number of objects and the largest object size"，且任何只泄漏这两项的方案必然承受与最大对象尺寸挂钩的最小带宽开销 [后半转述]；packing-based 设计 "leak information about the sum of plaintext object sizes"。
  - slides：oblivious stores "are still vulnerable to length leakage attacks"；基线安全模型 "assumes the stored values have the same size"。动机：真实数据 object sizes 可相差 "several orders of magnitude"。
  - 出处 [待核] — [USENIX 页面](https://www.usenix.org/conference/usenixsecurity24/presentation/jia-grace)、[PDF](https://www.usenix.org/system/files/usenixsecurity24-jia-grace.pdf)、[ePrint 2024/863](https://eprint.iacr.org/2024/863.pdf)、[slides](https://usenix.org/system/files/usenixsecurity24_slides-jia_grace.pdf) [待核·搜索摘录]
  - 覆盖要素：①②③ **三要素齐备**。
- **Blackstone, Kamara, Moataz, "Revisiting Leakage Abuse Attacks"（NDSS 2020）**
  - 原句（转述+部分原句）：四个新攻击中三个只用 document-size 泄漏，因此 "also work against ORAM-based solutions"；定义 "volume pattern" = 匹配文档大小集合、"total volume pattern" = 其和；Enron 实验。
  - 出处 [待核] — [ePrint 2019/1175](https://eprint.iacr.org/2019/1175)、[NDSS PDF](https://www.ndss-symposium.org/wp-content/uploads/2020/02/23103-paper.pdf) [待核·搜索摘录]
  - 覆盖要素：②（文档大小本身是独立泄漏面，ORAM 不防）。
- **vORAM（Roche, Aviv, Choi, S&P 2016）**：原句 "the first ORAM to allow varying block sizes without trivial padding" — [arXiv 1505.07391](https://arxiv.org/pdf/1505.07391) [待核·搜索摘录]。覆盖 ②③。
- **TaoStore（Sahin, Zakhary, El Abbadi, Lin, Tessaro, S&P 2016）**：原句 "We consider oblivious storage systems hiding both the contents of the data as well as access patterns from an untrusted cloud provider."；场景 "multiple users from a trusted group (e.g., corporate employees) asynchronously access and edit potentially overlapping data sets through a trusted proxy mediating client-cloud communication." — [TaoStore PDF](https://sites.cs.ucsb.edu/~rachel.lin/papers/TaoStore-CameraReady.pdf) [待核·搜索摘录]。覆盖 ①③。
- **Respire（CCS 2024）**：原句 "we focus on the setting where each database record is 256 bytes" — [ePrint 2024/1165](https://eprint.iacr.org/2024/1165.pdf) [待核·搜索摘录]。反证：主流单服务器 PIR 以定长小记录为设定。

#### PETS
- 未找到 PoPETs 2024–2026 中直接陈述 C 三要素的原句；Mohito 填充句（见 Q1）覆盖 ②（假设消息同长，指出可引入更高效填充）。

#### VLDB/SIGMOD
- **Pantheon README [直接核]**："Consider a cloud server that owns a key-value store and provides a private query service to its clients. The key-value store in this case is _public_ and a client cannot encrypt or modify it to ensure privacy. Pantheon is a system that allows its clients to retrieve the value corresponding to a key from such a key-value store privately, i.e. without letting anyone else in the world (even the server) to know which key the client is interested in." — [README](https://raw.githubusercontent.com/ishtiyaque/Pantheon/main/README.md)。覆盖 ①；③ 为反例（公开明文）。
- **Pantheon §2.2 威胁模型（转述）**：被动敌手可 "see the content of the key-value store and monitor and store all queries and responses from clients"、"monitor and analyze any operation the server performs and mount side-channel attacks on the server"、"monitor, log, and analyze all network traffic" — [ePrint 2023/1331](https://eprint.iacr.org/2023/1331.pdf) [待核·搜索摘录；章节号来自摘录]。
- **SWAT（PVLDB 2024）**："Keys and equal-length values" — 见 C-Q1；② 为显式等长假设（反证）。

#### 其他 venue / 预印本
- **Snoopy（Dauterman, Fang, Demertzis, Crooks, Popa, SOSP 2021）**
  - 原句："Encryption cannot fully protect this data: how the user accesses data can leak sensitive information to the cloud. - **ShieldDB（arXiv 2003.06103）**：[转述] "ORAM does not hide the size of query results unless non-trivial padding is added" — [arXiv](https://arxiv.org/pdf/2003.06103)。覆盖 ②。
- **Tiptoe（SOSP 2023）变长处理**："SimplePIR serves data to the client only in relatively large chunks—roughly 40 KiB with our parameter settings. The client must always fetch at least one of these chunks from the server."；"group URLs into batches and compress them, dropping any URLs that are more than 500 characters in length"；"we pad the height of the matrix M to the size of the largest cluster." — [ePrint 2023/1438](https://eprint.iacr.org/2023/1438.pdf) [待核·搜索摘录]。覆盖 ②。
- **Nakamori, Motomura, Fujiki, "Densely-Packed Single-Server PIR for Variable-Length Data"（EuroS&P 2025 [待核]）**
  - 原句："existing optimizations for variable-length records either add significant padding overhead or require complex key management."；"packs variable-length entries as efficiently as symmetric-key schemes but without any additional key management"；"more stable than the padding method across various data length distributions"；"Existing ways of handling records of different lengths either waste space on padding or depend on complicated key management"；含密钥传输时 "up to 1.8 times faster than the symmetric encryption method"。
  - 出处 [待核] — [Zenodo 16740584](https://zenodo.org/records/16740584) [待核·搜索摘录]
  - 覆盖要素：①②；③ 为"对称加密 + 密钥管理"路线的对照。
- **Q2 小结（C）**：①③ 是 ORAM/oblivious storage 文献的标准开场（ObliviStore 以加密邮件库为例）；② 由攻击方（Blackstone 2020）与防御方（Jia 2024）双向确认。三要素同现且以"归并到等尺寸容器"为契约的只有 Jia et al. 2024（bin 为单一最大尺寸，是否多档 [待核]）。

### 4.4 裁决（C）

- **Q3 占位判定**：未发现在可核证据上同时满足三条的系统 → C 不因占位降级。最接近者 Jia et al.（USENIX Sec 2024）与 Nakamori et al.（EuroS&P 2025 [待核]）须正面对照。
- 逐 venue 家族：
  - **WWW：不可投**（Q1 空）。
  - **SIGIR：不可投**（Q1 空）。
  - **VLDB/SIGMOD：可投但须正面对照** Towards Practical Oblivious Map（VLDB 2025）、OasisDB（VLDB 2025）、SWAT（VLDB 2024）、NSHEDB（SIGMOD 2026）、Femur（SIGMOD 2025，公开 KV）、Pantheon（VLDB 2023，公开 KV）；并须对照 Jia et al. 2024 / Nakamori et al. 2025 / vORAM。
  - **安全四会：可投但须正面对照** Jia et al.（USENIX 2024，最近邻）、Treebeard / V-ORAM（USENIX 2025）、DDR-SSE（USENIX 2026）、vORAM（S&P 2016）、Pancake（USENIX 2020）、单服务器 PIR 原语线（YPIR / Respire / ZipPIR 定长）、HHG 2013。
  - **PETS：可投但须正面对照 CODoH（2026）、Mohito（2024）、SWiSSSE（2024）**，证据为弱：CODoH 依赖 TEE 且主语为 DNS 缓存；Mohito 为 IoT 消息；SWiSSSE 为 SSE。若用户不接受这三者作为"托管加密对象存储点查"的接纳证据，则 PETS → 不可投。
- **裁决依赖的 [待核] 项与翻转**：(i) Jia et al. 2024 的 bins 是否支持多尺寸档且档位写入泄漏定义——若是，C 被占位（只能作对照）；(ii) Nakamori et al. 2025 的泄漏模型——若其为"按长度档/桶公开"的单服务器 PIR，C 被占位；(iii) Pancake 原文 §2 值长度假设（影响 Pancake 是否作为变长对照）；(iv) PETS 三篇的角色/信任模型字段全部 [待核]。
